# POP BASE（ポップベース）

キャラクターのポップアップが10〜14日ごとに入れ替わるバーチャルポップアップショップ（運営: スタジオハヌル）。
自社キャラクターのほか、他社のキャラクターのポップアップも開催します。
お客さんはキャラクターのアバターで 3D の店内を歩き、棚の商品を手に取って購入できます。
同じ時間にいる他のお客さんのアバターも見え、スタンプで反応し合えます。

## 全体の構成

```
お客さんのブラウザ（/）
 ├─ 3D 店内（Three.js）……… アバターで歩く・棚の商品を手に取る
 │                              レジ（カート）・出口（EXIT）も店内に
 ├──▶ Shopify（Storefront API）… 商品・価格・在庫・購入手続き、公開中の内装と配置
 └──▶ サーバー（server/）…………… 他のお客さんの位置・スタンプを中継

スタッフのブラウザ（/admin）… 店内管理画面
 └──▶ サーバー（server/admin/）… ログイン・下書き保存・公開・画像アップロード
       └──▶ Shopify（Admin API）… 内装・配置をメタオブジェクトに保存、画像を「ファイル」に保存
```

| 管理するもの | どこで | 誰が |
| --- | --- | --- |
| 商品・価格・在庫・商品画像・決済 | Shopify 管理画面（いつもの商品管理） | 社内スタッフ |
| 棚の配置・内装（壁紙・床・色）・会期・看板の文字・フォント・入口の画面・キャラクター紹介・アバター | **店内管理画面 `/admin`**（プレビューを見ながら編集 → 公開） | 社内スタッフ |
| 内装テーマのひな形・キャラクター | `js/themes.js`・`js/data.js`・`js/art.js` | 技術担当 |
| サーバー・アカウント | `server/`、`npm run admin:user` | 技術担当 |

- スタッフ向けの操作説明：**[docs/admin-guide.md](docs/admin-guide.md)**
- Shopify とつなぐ初期設定：**[docs/shopify-setup.md](docs/shopify-setup.md)**

Shopify を設定しない間は、`js/data.js` の見本の商品で動き、店内管理画面の内容はサーバーの `data/` フォルダに保存されます
（デモ用の注文完了画面）。

## 動かす

Node.js 18 以上が必要です。

```bash
npm install
```

```bash
npm start
```

→ お客さんのサイト http://localhost:8080 （同時接続サーバーも一緒に起動します）

別のブラウザ（またはシークレットウィンドウ）でもう1つ開くと、お互いのアバターが見えます。

> 3D 店内は ES モジュールを使うため、`index.html` をファイルとして直接開くと表示されません。必ずサーバー経由で開いてください。

### 店内管理画面を試す

1. 別のターミナルで、管理画面のアカウントを作ります（パスワードを2回聞かれます。10文字以上）

```bash
npm run admin:user -- staff01
```

2. http://localhost:8080/admin を開いてログイン
3. 商品をドラッグして棚に置いたり、壁紙や色を変えたりすると、右のプレビューにすぐ反映されます
4. 「下書きをサイトで確認」で実際のサイトを確認し、「公開する」でお客さんのサイトに反映されます

### 公開する

サーバー1つで **サイト配信と同時接続の両方** を行います。Node.js と WebSocket が動くサービスならどこでも公開できます
（例: Render、Fly.io、Google Cloud Run、Railway、VPS など）。

**popbase.jp（Render）で公開する手順は [docs/deploy-render.md](docs/deploy-render.md) にあります**（設定は `render.yaml`）。
サーバーは必ず **1台** で動かしてください（店内の人数・待機列をサーバーのメモリで管理しているため）。

| 環境変数 | 既定値 | 内容 |
| --- | --- | --- |
| `PORT` | 8080 | 待ち受けポート |
| `MAX_VISITORS` | 50 | 店内に同時に入れる人数（部屋は1つ）。超えたら入口で待機 |
| `VISIT_MINUTES` | 30 | 混雑中（待っている人がいるとき）の1人あたりのお買い物時間 |
| `WARN_MINUTES` | 5 | 終了何分前から残り時間のタイマーを出すか |
| `RECONNECT_SECONDS` | 30 | 再読み込み・通信の切れ目で、店内の場所・待機の順番・残り時間を預かる秒数 |
| `MAX_PER_IP` | 6 | 同じ IP からの同時接続の上限 |
| `ALLOWED_ORIGINS` | なし | 接続を許可するサイトの URL（カンマ区切り）。本番では設定を推奨 |
| `SHOPIFY_STORE_DOMAIN` / `SHOPIFY_ADMIN_TOKEN` | なし | 設定すると店内管理画面の保存先が Shopify になる（[手順](docs/shopify-setup.md)） |
| `SESSION_SECRET` | 自動生成 | 管理画面のログイン Cookie の署名鍵。サーバーを複数台にする場合は同じ値を設定 |
| `COOKIE_SECURE` | なし | `1` で Cookie を HTTPS 限定にする（本番は HTTPS で公開し、`1` を推奨） |
| `DATA_DIR` | `./data` | 管理画面のアカウント・（Shopify 未設定時の）下書きと画像の保存先 |
| `CLIENT_IP_HEADER` / `TRUST_PROXY_HOPS` | なし / 1 | お客さんの接続元 IP の読み方（中継サーバー越しに公開する場合。`server/client-ip.js`）。公開後に `/api/ip` で確認 |
| `ADMIN_INITIAL_USER` / `ADMIN_INITIAL_PASSWORD` | なし | アカウントが1つもないとき、起動時にこのアカウントを作る（コマンドを打てない公開サービス向け。作ったら消す） |

**本番で気をつけること**
- 管理画面は必ず **HTTPS** で公開してください。
- `data/` フォルダ（アカウント情報など）は、再起動やデプロイで消えない場所（永続ディスク）に置いてください。
  消えるサービスでは、保存先を Shopify にし、アカウントは起動時に `ADMIN_PASSWORD` 付きで `npm run admin:user` を実行して作る運用にします。
- `data/` は Git に入らないよう `.gitignore` 済みです。

サイトだけを別の場所（Shopify のページ、GitHub Pages など）に置く場合は、`js/data.js` の `SHOP.multiplayerUrl` に
サーバーの URL（例: `wss://popup-server.example.com/ws`）を書きます。サーバーにつながらないときは、
「ひとりで見ています」と表示されて、そのまま店内を歩けます。

状態確認: `/healthz` で、店内の人数・待機中の人数・混雑中かどうかが JSON で返ります。

## できること

| エリア | 内容 |
| --- | --- |
| 入口 | テーマ色のグラデーションとキャラクターのお出迎え、ドアが開く演出。文字・ロゴ・背景画像・色・お知らせは管理画面で変更 |
| 3D 店内 | 入口で「お店に入る」→ アバターを選んで入店（名前の表示・入力はなし。店内の「アバター」ボタンで変更もできる）。左右の棚・会場限定テーブル・レジ・出口。棚に近づくと「この商品を見る」、クリックでも詳細が開く。全画面表示でも商品詳細・カートがそのまま開く |
| 同時接続 | 他のお客さんのアバターが見える（名前は出さない）。スタンプ 6 種。アバターは管理画面で追加・選択できる |
| 会期・営業時間 | 管理画面で開始・終了の日時と毎日の営業時間を設定。営業時間外は入店できず（サーバー側で管理）、閉店5分前からタイマー、閉店時刻に自動で退店。会期の表示は日時から自動で作成 |
| 入場制限 | 店内は1部屋・同時に50人まで。満員なら入口で待機（「入店まであと○人／目安○分」）、空いたら自動で入店。待っている人がいる間は1人30分まで、終了5分前からタイマー表示、時間になると自動で退店しカートは空になる |
| 商品詳細・カート | 数量選択、お一人様の購入上限、特典までの残額メーター、送料無料ライン |
| 購入手続き | Shopify 連携時は Shopify のチェックアウトへ |
| 退店 | 店内の手前の壁の「EXIT」のドアから。退出するか・カートが空になることを確認してから退店（席はすぐ空く） |
| 壁のキャラクター | 話しかけるとプロフィールが出る |

商品は店内の棚でだけ販売しています（いわゆる「商品一覧ページ」はありません）。お店を歩いて探す体験を大切にするためです。

| | PC | スマホ |
| --- | --- | --- |
| 歩く | WASD / 矢印キー、床をクリック（1回で約3m進む） | 左下のスティック、床をタップ（1回で約3m進む） |
| 視点 | ドラッグ（店内をつかんで動かす向き）、Q / E、ホイールでズーム | スワイプ |
| 全画面 | 右上の「全画面」 | 右上の「全画面」（iPhone でも画面いっぱいに表示） |
| カート | 右上の「カート」、またはレジに近づく | 同じ |
| 商品を見る | 近づいて Enter、または商品をクリック | 近づいて表示されるボタン、または商品をタップ |
| スタンプ | 右下のボタン、1〜6 キー | 右側のボタン |

### 混雑テスト（50人のときの動きを試す）

自動で歩き回るお客さん（ボット）を店内に入れて、混雑したときの動きを確かめられます。
ボットは本物のお客さんと同じ手順（入店 → 待機 → アバター選択 → 歩く・スタンプ）でつながります。

1. 同じパソコンからたくさん接続できるように、サーバーを `MAX_PER_IP=100` を付けて起動します（テストのときだけ）

```bash
MAX_PER_IP=100 npm start
```

（Windows の PowerShell では `$env:MAX_PER_IP=100; npm start`）

2. 別のターミナルでボットを入れます

```bash
npm run crowd
```

3. ブラウザ（またはスマホ）で http://localhost:8080 を開いて入店すると、店内 50 人の状態になります

| 試したいこと | コマンド |
| --- | --- |
| 50人（自分＋ボット49人） | `npm run crowd` |
| 満員・待機画面（ボット60人＝10人が待機。自分は待機列の最後に並ぶ） | `npm run crowd -- 60` |
| お客さんの入れ替わり（ボットが2〜4分で自分から退店） | `npm run crowd -- 60 --stay 3` |
| 別のパソコンのサーバーで試す | `npm run crowd -- 49 --url http://192.168.1.23:8080` |

5秒ごとに、店内・待機の人数と、混雑中かどうか、通信量が表示されます。止めるときは `Ctrl + C`（ボットは全員すぐ退店します）。

**30分の時間制限やタイマーを短い時間で試す**ときは、サーバーを次のように起動してから `npm run crowd -- 60` を実行します（上限50人・お買い物時間2分・終了1分前からタイマー）。

```bash
MAX_PER_IP=100 VISIT_MINUTES=2 WARN_MINUTES=1 npm start
```

> スマホでの見え方・動きの重さは、同じ Wi-Fi のスマホから `http://（パソコンのIPアドレス）:8080` を開いて確かめてください。
> 本番では `MAX_PER_IP` は付けずに（または小さめの値で）起動してください。

### 入場制限について

- お買い物時間の制限がかかるのは、**満員で待っている人がいるときだけ**です（空いているときは制限なし）。
  混雑が始まった時点ですでに30分を過ぎていた人には、そこから5分の猶予があります。
- 時間内に、**店内で会計まで済ませてもらう**想定です。Shopify 連携時は「購入手続きへ」で Shopify の画面に移った時点で店内からは出ます
  （Shopify の購入画面には時間制限はかかりません）。
- 入場制限は、このサーバー（`npm start`）につながっているときに働きます。サーバーなしでサイトだけを公開した場合は制限なしで入店できます。
  また、ブラウザ側の仕組みを意図的に壊せば制限を回避できるため、限定品の購入数の上限は Shopify 側でも設定してください。

### 荒らし対策

同時接続でやり取りするのは **入店券・位置・アバターの種類・スタンプの番号だけ** です。
自由入力のチャットや名前はないので、不適切な書き込みは起こりません。サーバー側でも値の範囲チェック、
送信回数の制限、IP ごとの接続数制限を行っています。

## 内装テーマ

テーマのひな形は **`js/themes.js`** にあります（`sky` / `night` / `holiday` / `spring`）。
イベントごとの細かい変更（壁紙画像・色・会期・看板の文字）は、Shopify のメタオブジェクトでひな形を上書きします。

- 確認用: URL に `?theme=night` を付ける、または店内の下の「内装テーマ（確認用）」で切り替え（Shopify 連携時は非表示）
- 新しいひな形: 既存テーマをコピーして色・柄を変更

| キー | テーマ | 壁 | 床 |
| --- | --- | --- | --- |
| `base` | Lavender Base（POP BASE の基本・初期設定） | ラベンダーの水玉 | クリームのタイル |
| `sky` | Sky Walk 空のおさんぽ | 雲柄 | 木目 |
| `night` | Starry Night 星降る夜のおさんぽ | 星柄（夜の照明・ネオン看板） | カーペット |
| `holiday` | Holiday Party ハヌルのホリデーパーティー | ストライプ＋緑の腰壁 | 赤白チェック |
| `spring` | Spring Picnic はるのピクニック | 花柄 | タイル |

## キャラクター・アバターについて

キャラクター（ハル・ビョル・タルビ・ゴミ）は **仮のオリジナルデザイン** です（`js/art.js` の SVG）。
アバターは 3D モデルではなく、キャラクターの絵を「常にこちらを向く立体の板」にして歩かせています。
実際のキャラクターに差し替えるときは、`js/data.js` の `CHARACTERS` と `js/art.js` の絵を入れ替えてください
（将来 3D モデル（glTF）を用意した場合も、`js/world/avatars.js` の差し替えで対応できます）。

## 今後の拡張候補

- **Shopify 管理画面への組み込み**：今の店内管理画面は独自のログインです。Shopify のアプリとして登録すると、
  Shopify 管理画面の中から（Shopify のアカウントのまま）開けるようにできます。

## ブランドデザイン（POP BASE）

- ロゴのマーク: `images/popbase-mark.svg`（ロゴの見本から作った仮のデータ。正式なロゴデータが届いたら同じ名前で差し替える）
- カラー: ラベンダー `#DCCEF5`・ピンク `#F7C9D8`・クリーム `#FFF4F1`・濃色 `#2E2729`（`css/style.css` の `--brand-*`）
